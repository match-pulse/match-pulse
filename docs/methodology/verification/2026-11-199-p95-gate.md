## 1. Claim or Acceptance Criterion

FND-004: the elasticity target is measured and asserted, not only observed. Registration and v3 ticket-purchase bursts must fail when p95 reaches or exceeds 1,000 ms.

## 2. Method

- Added `expect(p95).toBeLessThan(1000)` to the 100-request registration burst.
- Added a 20-buyer concurrent ticket-purchase burst with the same p95 assertion, a no-oversell check and a 20-ticket count.
- Ran both bursts and the full database/CLI suites.

## 4. Result

- The registration burst fails if p95 is 1,000 ms or more.
- The ticket burst fails if p95 is 1,000 ms or more, any purchase fails, or the committed ticket count is not 20.
- FND-004 is Verified for the CI environment.

## 5. Limitations

- The values are environment-specific to the local/CI PostgreSQL instance. The dedicated Domain invariants job enforces the 1,000 ms assertion; the post-matrix fault job runs the restored suite with `P95_STRICT=false` because repeated resets load the runner. The fault job still validates every mutation.
- Production and multi-instance load are not measured; that belongs to the final production deployment step.
- The scheduled 20/50/100 performance script remains a baseline, not a production capacity claim.
