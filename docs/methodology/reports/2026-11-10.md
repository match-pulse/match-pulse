# Methodology Submission — Checkpoints A–E

This is the cover for the Development Methodologies deliverable. The deliverable is
the five checkpoints, not a separate long report. Each checkpoint is one page and
about three minutes.

## The project in two sentences

MatchPulse is a club-first football ticketing and fan-engagement platform. The
methodology question is how a solo developer keeps a small end-to-end increment
honest when the domain rules, the evidence and the product direction are all
moving.

**Claim.** For a club organizer running a match day, MatchPulse keeps ticket sales
and prediction trades correct under concurrent requests — never overselling,
never charging twice, never paying a winning share twice, and never exposing
another club's data — with the limitation that commerce is simulated, the
evidence is local/CI, and there is no hosted deployment or independent user study.

## The five checkpoints

| Checkpoint | Course question | One-line answer |
| :--- | :--- | :--- |
| **A** | Context, claim and first evidence | One capacity claim, tested with a 100-request burst and observed-red fault injection |
| **B** | Operating model and feedback | Hybrid lifecycle: plan-driven domain contract, iterative delivery, adaptive scope |
| **C** | Quality and residual risk | Five risks, one non-test control, one double-spend evidence story, honest residual risk |
| **D** | Architecture and changeability | Modular monolith, database boundary, v3 tenancy as the realistic change |
| **E** | Delivery, observation and recovery | Local/CI delivery, health/logs/smoke, public-schema restore, no production claim |

## Agile operating model

The work moves in small slices with one implementation PR in progress. Each slice
has an issue, a bounded scope, a failing-or-observed test, CI and a review
decision. The domain contract is stable; the delivery is iterative; the scope is
adaptive. Documentation is written just in time: the kata for the problem, the
characteristics for the qualities, the ADRs for decisions, the checkpoints for
evidence, and the verification records for detail.
